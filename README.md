GitHub Pages 发布静态活动信息，评分和看板使用独立云服务与 SQLite 数据库。前端零构建依赖，后端仅使用 Python 标准库。

## 本地预览

```sh
python -m http.server 4173 --bind 127.0.0.1
```

此命令只预览公开活动信息。完整平台需要 Python 3.11+：

```powershell
$env:GOTC_DATA_DIR = '.runtime/local-data'
$env:GOTC_PORT = '5274'
$env:GOTC_PUBLIC_ORIGIN = 'http://127.0.0.1:5274'
python -B server/app.py
```

打开 http://127.0.0.1:5274/gotc/ 。首次运行的管理码保存在指定数据目录的 `admin-access.txt`，不要提交或公开。提交到 `main` 后由 GitHub Actions 验证并发布官网；云端发布方式见 [部署说明](deploy/README.md)。

## 维护内容

- `index.html`：公开活动内容与日程。
- `styles.css`：响应式样式。
- `app.js`：日程切换、清单、复制链接与导航。
- `platform.html`、`platform.css`、`platform.js`：评分工作台、后台与实时看板。
- `server/app.py`：身份认证、评分、投票、SQLite 持久化与静态服务。
- `assets/`：活动现有主视觉和报名二维码。
- `downloads/`：日历与作品提交清单。

页面以 2026 年 10 月学校交流版为活动信息基础。新版展示评审先记录评语，分值、汇总和晋级规则尚未实现；现场细则、GOTC 详细场地和最终组织安排以主办方通知为准。旧 9 月活动的观众加分、后台、队伍及学生数据未接入本官网。

## 发布范围

仓库包含平台源码和公开活动素材，不包含聊天记录、报名数据、数据库、管理码、评委邀请码、API 密钥或内部方案文件。作品采用链接式提交，不上传文件；作品提交清单可公开查看。

新数据库初始无参赛队伍、评委或评审记录，展示评审窗口默认关闭。组织方先录入本届队伍、发放邀请码，再配置本轮队伍和评委名单。公开进度每 2 秒更新，大屏模式每 12 秒轮播 8 支队伍；记录数量不代表成绩。旧单阶段评分接口保留原有行为，详见服务端说明。

## 作品提交

组织方先录入队伍，在后台的“作品提交管理”为每队生成独立提交码并单独发放，再打开作品提交窗口。提交码只显示一次；重发或停用会立即作废该队旧会话，保留已保存材料。没有公开注册，也不收集成员联系方式。

队伍在“作品提交”保存草稿，填写作品名与介绍、仓库/代码包、README、许可证说明、展示材料、视频、来源与局限，以及演示链接或本地演示说明。草稿允许缺项，正式提交需要完整填写并确认自查；代码版本和许可证文件链接选填。所有链接必须为 HTTPS，外链可访问性、许可适用性、材料页数和视频时长由队伍自行检查。

草稿不覆盖评委可见的最近正式材料，再次正式提交才更新正式版本和公开作品名称。多人编辑遇到版本冲突时，输入会保留，可查看最新草稿后自行合并。平台保存字段和链接，外部链接内容仍可能改变，不提供内容存证。

作品提交开关独立于评分与投票，默认关闭、未设截止。后台截止时间按北京时间填写，服务器到点锁定；补交需管理员延长截止并重新开放。建议先关闭提交再评审。评委只读正式材料；后台可检查草稿和正式材料并单独导出提交 CSV，原评分导出保留。

旧数据库首次升级会在私有数据目录备份并事务迁移账号角色约束，保留原账号、会话、评分与投票。请保留持久化数据目录，不以删库方式升级。本功能不改变当前评分、排名或晋级算法。

## 展示评审框架

评委入口现使用独立展示轮次：组织方选择本轮队伍和评委、开放窗口，首次开放时冻结队伍信息与正式项目材料。评委可保存观察意见草稿、提交正式定性记录、修改或回避；多人编辑通过版本检查防止静默覆盖。关闭或截止后只读，新建轮次保留旧轮次记录。

**当前尚未实现数值评分和结果计算。** 满分、有效评委人数、汇总公式、晋级名额均为明确的空值；页面不会给出成绩、排名或晋级结果，发布操作会被阻止。公开页面仅展示已提交定性记录的数量，不能把它解释为成绩。旧单阶段分数保留在兼容接口，既不自动迁入新轮次，也不参与新版展示进度。

新评审窗口独立于作品提交、旧评分及观众投票。后台可修改尚未首次开放的关闭轮次名单；首次开放冻结后，无论是否已有评审记录，更换名单或材料都需有理由新建轮次，关闭后重开不会刷新快照。框架不包含自动配置规则、路演计分或晋级算法。
