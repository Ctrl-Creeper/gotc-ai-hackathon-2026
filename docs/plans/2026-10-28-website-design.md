# 活动官网设计

采用零构建依赖的 HTML/CSS/JavaScript 前端，在独立公开仓库通过 GitHub Pages 发布活动官网。评分工作台、观众投票、后台和实时看板由独立的 Python 标准库服务和 SQLite 支撑，部署在现有服务器 /gotc/ 路径。首屏采用现有“百格成城”蓝色城市主视觉，配以大字、方格、橙色点缀。

信息优先级：10 月最新学校交流版确定年龄、组队、方向、日程和单位；完整方案补充评分权重和提交清单。六维权重明确标注“方案版”，GOTC 下午详细议程标注“建议安排”。旧 9 月活动的五维 125 分制、后台链接和个人数据均不迁入。

日程使用可键盘操作的标签页，无 JavaScript 时仍能阅读所有日程。作品清单在浏览器本地保存。提供日历下载、清单下载、打印和分享链接。看板每2秒轮询，屏幕模式每12秒轮播8队。专业均分默认至少5份有效提交，草稿/回避不计入，同分并列。观众票独立计数，每个观众码最多支持3支队伍。

选择单机标准库服务是因为现场约200人，无需引入前端构建、付费数据库或跨域认证。SQLite WAL事务保证改分和投票的原子性；部署使用独立用户、进程、数据目录和端口，避免影响现有活动。折中是需要维护单台服务器，不能声称支持跨地域容灾。发布前备份、健康检查和失败回滚；现场前仍应使用正式队伍做组织方彩排。

邀请码使用高熵随机值，数据库只保存scrypt哈希；会话使用HttpOnly/Secure/SameSite Cookie，同源校验保护写操作。后台必须认证，公开API不含评委身份、反馈或单份评分。数据与管理码不进入Git或静态发布包。

验收采用API端到端测试、看板排序/转义/轮播测试、公开资源检查、线上TLS与API健康检查。本地浏览器预览权限未获允许，未进行浏览器视觉验收，不能把代码级响应式检查描述为已完成浏览器验证。
